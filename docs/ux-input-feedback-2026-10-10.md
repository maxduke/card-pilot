# UX 第一批：金额输入与操作反馈 · 2026-10-10

对应 [产品评估](product-ux-review-2026-10-10.md) 的 O01、O02、O05、O06，及草稿恢复页的大字号可操作性。基于已合并 Batch A 的最新主线 `43795d6` 实现。

## 行为

- 新增交易只在新表单没有金额输入、也没有明确选择币种时，随换卡带入账户默认币种。已有金额、手动币种及恢复草稿保留原单位；未完成金额字符串也受保护。额度币种文案不再称为账单币种。
- 金额展示保留精确数值，仍使用当地分组与小数格式。如果 NumberFormatter 的输出不能精确往返，则显示本地化的精确 Decimal 文本；不更改已保存金额。促销剩余 `0.001` 不再显示为 `0`。
- 新增交易回到初始表单状态时直接关闭，并清理空草稿；有修改或从磁盘恢复的草稿继续要求保留／丢弃选择。恢复页先显示金额、币种、卡片、日期和商户，并可滚动以适应辅助字号。摘要按草稿保存的金额格式解析。
- 首页还款反馈提供关闭与至少 44 pt 的撤销／关闭动作，辅助字号时改为纵向布局。普通显示 8 秒后收起；VoiceOver 开启时保留供用户处理。页面离开、应用失活或日期／常用时区变化后清理反馈；账期详情始终保留持久撤销入口。

不引入数据库字段、迁移、草稿版本或额外状态框架；保持当前业务计算、手动促销分配、备份格式和本地提醒规则。

## 回归与验证

- 金额格式回归覆盖六个地区、小额、高精度、极小数与大整数，以及未达标差额的显示和计算一致性。
- UI 回归覆盖换卡后的金额／币种实际保存、空金额跟随默认币种、主动选择同一个币种后的保留、空金额草稿恢复后的换卡、未经修改直接关闭和重新启动后无草稿。
- 扩展已有地区变化 UI 用例，验证恢复摘要将 `de_DE` 的 `1,500` 显示为 `1.5 CNY`。
- 模拟器测试数据增加一个港币账户与卡片；其完整备份往返仍由原生持久化测试验证。
- 本地金额、草稿、交易和促销隔离回归共 58 项通过，0 失败。隔离环境不验证 SwiftUI、UIKit、SwiftData 和真实键盘。全部 Swift 源码语法检查通过；后续恢复页调整的相关文件也再次通过语法检查，diff 检查通过。
- [首轮原生 workflow](https://github.com/maxduke/card-pilot/actions/runs/38054418049) 已通过 Xcode 构建及全部 199 项单元／集成测试，但两个新增换卡 UI 场景失败：打开选择页后主线程忙碌，以及输入商户后测试向错误方向寻找已滚出屏幕的按钮。已将选择弹层移出惰性 Form 行、打开时解除金额焦点，并修正首行按钮的测试查找方向；最终原生验收仍以 [PR #22](https://github.com/maxduke/card-pilot/pull/22) 当前提交的 `iOS` workflow 为准。

## 真机验收

1. 输入金额后跨人民币／港币卡换卡，手动选币种再换卡，保存并重新打开核对金额和单位。
2. 记录 `99.999`、计入目标 `100` 的活动，显示准确剩余金额；检查窄屏和辅助字号下长金额是否可读。
3. 空交易关闭，修改后保留／丢弃，草稿跨地区恢复，停用／删除原卡后更换卡片。
4. 连续标记不同账户已还，撤销只作用于当前提示对象；关闭提示后还款状态仍保留。切后台、切 Tab、跨日后不显示旧提示。
5. 开启 VoiceOver，提示不自动消失；最大辅助字号下，恢复草稿摘要和三个动作可滚动到达，还款提示操作可读、可点。

本批不宣称已完成真机、VoiceOver 或完整视觉验收。通知引导 O03 与其他无障碍问题 O04 留到下一批按场景实现和验收。
