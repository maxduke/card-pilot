# 交易输入、草稿与保存的 Release 测量

O19 已有读取性能基线，但快速输入、草稿写盘和提交尚未测量。字段变化会同步调用草稿保存；这条源码路径本身不能证明输入卡顿，也不足以支持引入防抖或并发写入。

本批先补齐测量，没有改变草稿频率、交易校验、保存、回滚或清理规则。

## 测量范围

复用既有的隔离模拟器存储与 100／5000／20000 笔交易数据，每个用例使用独立 UUID、20 张卡、610 个账期和 24 个促销。固定简体中文、中国地区、上海账本时区和普通字号，指定同一张合成卡片。

| 环节 | 测量窗口 | 窗口外的准备与核对 |
| --- | --- | --- |
| 金额输入 | 聚焦后连续输入 `123456.78`，直到字段精确读回 | 每次新建表单；清理上一次草稿 |
| 商户输入 | 聚焦后连续输入 `Performance merchant 0123456789`，直到字段精确读回 | 预填金额；最后一次输入后退到后台、终止并重启，继续草稿并核对卡片和原始字段 |
| 保留草稿 | 点击确认弹窗中的“保留草稿并关闭”，直到表单消失 | 预填字段、打开确认弹窗；下次采样前核对草稿概要并丢弃，最后一次重启后核对恢复字段 |
| 确认保存 | 从促销确认页点击“确认并保存”，直到表单消失 | 输入、自动促销选择及步骤切换；采样结束后核对总笔数、唯一匹配、金额和卡片，再重启读回 |

每项使用 XCTest 的十个有效样本及其预热。前三项不提交交易；保存项每次调用新增一笔，包括预热，因此数据规模从报告中的初始笔数增长。附件保留实际调用次数和最终总数；不将保存项描述为每个样本都有完全相同的笔数。

## 指标与边界

每个用例收集原生 Clock、应用内存和命名区间指标：

- `DraftSave` 包围草稿校验、JSON 编码、大小校验及原子受保护写入。
- `TransactionCommit` 包围 `TransactionEditActions.save`，包含该函数的校验、关系变更、持久化及失败回滚。

区间只在显式定义 `PERFORMANCE_TESTING` 的模拟器构建中编译，普通 Debug 和发行构建不包含新增观测逻辑。使用 Apple 的 [OSSignposter](https://developer.apple.com/documentation/os/recording-performance-data) 与 [XCTOSSignpostMetric](https://developer.apple.com/documentation/xctest/xctossignpostmetric/init(subsystem:category:name:))；配对 ID 区分每次调用，`defer` 保留抛错路径的结束事件。

Clock 包含原生 UI 自动化和就绪／值断言；应用区间不覆盖全部 SwiftUI 更新。保留 Xcode 原始单位、聚合结果和十个样本，不从 Clock 减去区间值来推断剩余渲染时间。模拟器结果也不能证明真机流畅度；如后续需要生产性能修复，仍须按实际问题补充应用栈或 Instruments 归因及可比较的修复前后证据。

## Workflow 与验收

新增手动 `iOS Transaction Writing Performance` workflow：`small` 运行四项原生预检，`full` 完整运行十二项。固定 macOS 15、Xcode 16.4、iPhone 16 Pro／iOS 18.5，Release `-O`，关闭调试器、testability、覆盖率及 sanitizer，串行执行。十次采样的表单准备和恢复核对位于用例总时长内，写入用例上限为 1200 秒，工作流上限为 150 分钟；原有读取基线的 600 秒限制保持原样。

汇总拒绝失败、跳过、用例重执行、进程重启、超时、重复用例、缺少区间、缺少样本、非有限数值及错误数据规模。完整写入基线必须有四个环节乘三个规模；四项小数据预检明确标记为诊断子集。既有 21 项读取 workflow、测试类及默认汇总契约保留。

当前实现仍待原生预检、完整十二项测量与原图验收，不将计划中的采样数记作实际结果。之后继续当前 HEAD 的必跑 231＋95＝326 项、适用审查和合并主线验证。
