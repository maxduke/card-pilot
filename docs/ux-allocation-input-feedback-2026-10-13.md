## 行为

首次尝试保存时，若所选活动的计入金额无法按草稿地区格式解析，或不是有效正数，字段旁显示原生错误图标和“计入金额应为大于 0 的数字。”。按当前活动的显示顺序定位到首个无效金额，以金额和错误组成的区域为目标；长活动标题完整换行。金额及提示作为独立的原生 Form 行，使用 [ScrollViewReader](https://developer.apple.com/documentation/swiftui/scrollviewreader) 及由活动 UUID 组成的稳定目标，一次滚动对齐到输入行顶部，为随后出现的错误保留下面的空间，避免整项长标题或其他核对说明占用目标位置。选择开关和金额之间保留视觉分组；核对说明独立换行，不纳入需要完整显露的金额与错误行。

修改为有效正数后提示自然消失；取消选择后金额输入及错误隐藏，重新选择保留原有手动输入。显示校验是当前编辑页的临时状态，不进入草稿或数据库。定位继续使用现有固定步骤说明和操作区，不强制重新打开键盘，不改变搜索词、交易金额、活动选择或手动分配。

固定操作区在现有垂直布局中直接占据空间，Form 的实际视口位于步骤与操作区之间，键盘出现时仍由系统调整布局。金额前持续显示“计入金额（币种）”说明，填写数字后仍能辨认字段含义；空输入使用草稿小数分隔符组成的 `0.00`／`0,00` 数字示例，避免重复字段名称。原生 plain 输入、说明和提交错误分别保留自身布局，不再使用未奏效的 contain 包装。辅助字号将活动摘要移到独立原生行，避免长标题与摘要合起来超过整个视口；普通字号的活动标题与摘要排列保留。

字段提示与保存校验共用现有地区格式的正数解析。金额超过交易、币种不同、活动条件或上限等现有提示继续作为核对说明；有效的手动分配仍可保存。活动删除或币种变更、原消费不可用、交易与币种校验、草稿 UUID 去重、退款确认及持久化回滚继续使用原路径。新的提交会清除上次整体错误，再执行完整校验；修改金额不会误清持久化等其他错误。
