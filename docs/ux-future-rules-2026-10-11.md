# UX 第十二批：未来账务规则管理 · 2026-10-11

基于第十一批已验证主线 `c0b460d`，接续 O16 的完整账期回查，为账户详情中已排定的未来版本提供修正和取消入口。

## 行为

- 账户摘要按现有实际状态明确为“未还账期／已还账期”，空列表说明同样指明未还；已有较早逾期事项仍按原顺序显示，分组不再称为“近期”。这里只调整文字，不改变范围、排序或还款事实。
- 点击某项未来规则打开其计划详情，显示该版本、取消后采用的前一版、生效账期的账单／还款日期变化及下一项计划。保留已有日期覆盖，因此日期预览反映覆盖后的实际推算结果。
- 修正复用账户编辑器，并预选点击的规则与生效账期；其他入口仍采用原有默认。未改变规则时不产生新版本，取消编辑仍保留修改保护。
- 仅可取消尚未生效的所选版本，操作前明确确认；保存时重新检查当前自然月、版本存在性和账户归属。基线、当前与历史版本不允许取消，之后的其他排期不受影响。
- 取消前验证原版本适用范围内已保存的日期覆盖，范围止于下一版规则；若会产生无效还款日期，显示受影响账期并提供调整入口，保留原计划。已关闭账户的存储事实仍检查日期一致性，不以页面可见性跳过校验。
- 仅删除所选未来规则，保留其他版本与账期 UUID、日期覆盖、还款状态和提醒目标身份。保存失败恢复关系并回滚，可重试；成功后触发现有提醒重排。

不改 Schema、备份格式、账期归属或账务计算，不引入通用命令框架、第三方依赖或新的规则编辑器。

## 验证

- 六项领域／持久化回归覆盖受保护及不存在版本、中间版本取消后的规则选择、受影响日期覆盖、下一版本边界、完整备份往返、提醒身份、失败注入回滚／重试、跨月再检查与账户归属。
- 模拟器独立场景包含两组账户和三版规则：一组有可保留的完整日期覆盖，另一组仅有还款日期覆盖，取消会使组合无效；在年初、普通日期和年末验证完整备份往返。
- UI 回归检查点选版本的编辑预填与保存、确认取消／保留、取消后重启读回与之后计划保留；最大辅助字号检查冲突说明、禁用取消、相关账期导航及点击区域审计。

本地 Swift 6 语法解析和 diff 检查为补充；实际取消校验与账务计算代码另在 Swift 6 下编译执行，通过历史保护、版本边界和日期覆盖检查。接续第十一批后，完整 GitHub iOS workflow 预计运行 216 项单元／集成测试和 38 项 UI 测试；最终 HEAD 全部通过并确认原生截图后合并，再验证 main。

日期是按现有规则推算，仍需按银行账单核对；真实提醒、最小屏幕和 VoiceOver 独立验收。

## 第二次原生回归与用例边界修正

[PR run 38168866431](https://github.com/maxduke/card-pilot/actions/runs/38168866431) 通过全部 216 项单元／集成测试，以及 35 项正常结束的 UI 用例；另外一项账户历史用例超时，不能将聚合结果视为完整 UI 通过。未来规则的普通／最大字号流程及拆分后的三项日期筛选全部通过。

账户历史用例打开年份、月份菜单后，在原生 `tap()` 内分别等待约 60 秒，随后记录未收到动画完成通知并继续执行。已还／未还查询、账期详情、标记还款和空结果均通过；到第 173 秒重启应用时已接近 180 秒上限，跨共享卡的持久化读回未完成。日志证明等待发生在 XCTest 的交互同步阶段，不能据此断言其底层原因是模拟器基础设施故障，也没有证据支持修改应用账务行为。

将这个用例按事实边界分为两项：较早已还账期的筛选、详情往返与清除；较早未还账期的标记还款及共享卡重启读回。两项各自启动原有 `accountHistory` 夹具；第二项仍在同一次用例内从 UI Shared 实际标记还款、重启，再从 UI Primary 以相同年月和已还状态查询，保持完整持久化与账户共享验证。原有全部断言、三个普通字号截图、44 点入口检查保留，并补充清除后恢复 23 个账期及清除按钮消失的检查；最大字号账期用例不变。

同批处理已有明确证据的促销长用例：[run 38155681989](https://github.com/maxduke/card-pilot/actions/runs/38155681989) 的两个分组菜单等待曾使其超时，而本次无该等待仍耗时约 120 秒。按可选金额与可选文字规则拆成两项独立的实际录入、折叠、跨分组保存和重启读回流程，每项保留一次分组切换。金额用例保留错误字段自动展开、上限／单笔门槛读回及最大字号说明；文字用例保留隐藏字段不清空、重启自动展开和未修改取消不提示。原有三张截图与全部断言保留，不依赖另一用例写入的数据。
