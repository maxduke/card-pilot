# UX 第十二批：未来账务规则管理 · 2026-10-11

基于第十一批已验证主线 `c0b460d`，接续 O16 的完整账期回查，为账户详情中已排定的未来版本提供修正和取消入口。

## 行为

- 账户摘要按现有实际状态明确为“未还账期／已还账期”，空列表说明同样指明未还；已有较早逾期事项仍按原顺序显示，分组不再称为“近期”。这里只调整文字，不改变范围、排序或还款事实。
- 点击某项未来规则打开其计划详情，显示该版本、取消后采用的前一版、生效账期的账单／还款日期变化及下一项计划。保留已有日期覆盖，因此日期预览反映覆盖后的实际推算结果。
- 修正复用账户编辑器，并预选点击的规则与生效账期；其他入口仍采用原有默认。未改变规则时不产生新版本，取消编辑仍保留修改保护。
- 仅可取消尚未生效的所选版本，操作前明确确认；保存时重新检查当前自然月、版本存在性和账户归属。基线、当前与历史版本不允许取消，之后的其他排期不受影响。
- 取消前验证原版本适用范围内已保存的日期覆盖，范围止于下一版规则；若会产生无效还款日期，显示受影响账期并提供调整入口，保留原计划。已关闭账户的存储事实仍检查日期一致性，不以页面可见性跳过校验。
- 仅删除所选未来规则，保留其他版本与账期 UUID、日期覆盖、还款状态和提醒目标身份。保存失败恢复关系并回滚，可重试；成功后触发现有提醒重排。

不改 Schema、备份格式、账期归属或账务计算，不引入通用命令框架、第三方依赖或新的规则编辑器。

## 验证

- 六项领域／持久化回归覆盖受保护及不存在版本、中间版本取消后的规则选择、受影响日期覆盖、下一版本边界、完整备份往返、提醒身份、失败注入回滚／重试、跨月再检查与账户归属。
- 模拟器独立场景包含两组账户和三版规则：一组有可保留的完整日期覆盖，另一组仅有还款日期覆盖，取消会使组合无效；在年初、普通日期和年末验证完整备份往返。
- UI 回归检查点选版本的编辑预填与保存、确认取消／保留、取消后重启读回与之后计划保留；最大辅助字号检查冲突说明、禁用取消、相关账期导航及点击区域审计。

本地 Swift 6 语法解析和 diff 检查为补充；实际取消校验与账务计算代码另在 Swift 6 下编译执行，通过历史保护、版本边界和日期覆盖检查。接续第十一批后，完整 GitHub iOS workflow 预计运行 216 项单元／集成测试和 34 项 UI 测试；最终 HEAD 全部通过并确认原生截图后合并，再验证 main。

日期是按现有规则推算，仍需按银行账单核对；真实提醒、最小屏幕和 VoiceOver 独立验收。
