# 新增交易草稿恢复

本批覆盖所有新增交易入口（底部“记一笔”、卡片详情、促销及交易列表）。编辑已有交易、建卡和编辑促销的进程终止恢复仍属后续范围。

## 行为

- 有未完成草稿时先提供继续、丢弃并新建或关闭；继续后恢复交易信息及促销确认步骤。关闭表单可选择保留草稿或丢弃。
- 输入变化时同步原子写入本地小文件，进入非活跃状态时补写；未改动的空表单、以及输入后全部改回初始状态的新表单不会留下草稿；已恢复的草稿保持可继续。金额保留原始字符串，包括未输入完成的内容；日期保存为自然日期键。
- 保留手动计入金额、自动勾选及手动排除状态，恢复初始化不会重新计算并覆盖这些选择。修改交易条件后仍使用现有候选与默认金额逻辑。
- 草稿不是交易，不计入进度、交易列表、JSON 完整备份或通知计划。保存成功后清除草稿，失败则保留输入。
- 新交易使用草稿 UUID；读取草稿和提交前检查当前数据库。即使交易保存后、清理草稿前退出，重开也不会再次记录该笔交易；数据库确认已保存后，清理文件失败也不阻止新建交易。
- 草稿文件绑定数据库路径。完整备份恢复使用新数据库路径，旧账本草稿不会进入恢复后的账本；UI 测试也使用独立路径。文件采用 iOS complete file protection，不打印输入字段。
- 损坏、未知版本、读取失败不会自动覆盖原草稿，可重试或明确丢弃。写入失败显示重试入口；单个草稿限制 1 MiB，超限不替换上一次成功保存的草稿。
- 卡片不可用时要求重新选择；活动已删除或进度币种改变时拒绝静默丢失/换算分配；关联原消费失效时要求重新选择或取消关联。

## 验证

新增 7 项存储测试：不完整金额与手动分配往返、账本隔离、提交后清理中断去重与清理失败继续新建、数据库查询失败保留草稿、非法/超大写入保护旧内容、损坏与未知版本明确丢弃、新草稿回到初始状态清理而恢复草稿保留。Linux Swift 6.1 隔离运行全部通过（使用实际草稿、自然日期和枚举源码）。

新增 3 条原生 UI 用例：终止进程后从另一入口恢复手动促销金额并只保存一次；保留后丢弃草稿不产生交易；草稿卡片删除后重新选卡并成功保存。全部 Swift 源码语法解析和 `git diff --check` 通过；原生编译、完整 iOS 单元/UI 测试与最终评审结果以交付 PR 为准。

仍需真机检查系统回收、锁屏文件保护与恢复后的键盘/大字号体验。跨日刷新、性能测量不在本批。
