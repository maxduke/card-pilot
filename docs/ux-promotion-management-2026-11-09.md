# 活动规则确认、已有交易分配与单期管理

本轮落实活动评估中优先的三项改进，沿用现有模型、备份格式和人工确认的计入事实。

## 行为

- 保存前确认完整显示累计门槛、累计计入上限、单笔门槛，或逐笔优惠的笔数上限和单笔门槛。累计门槛高于计入上限时，在金额分组与保存前确认中提示按建议金额无法达标；仍允许保存，用户可按银行条款手动修正。
- 从活动详情选择已有交易时，候选按“推荐交易”和“其他交易（手动核对）”分组，保留搜索和手动选择。金额拥有持续可见的币种说明、收键盘入口和提交后的就地正数校验；修正后提示消失。退款超额确认、跨币种手填、交易去重和保存回滚继续使用原路径。
- 系列删除确认明确期次、有效期及其他期保留。详情“更多操作”提供归档或恢复，确认提示说明单期范围、已有交易及进度保留；归档不改变系列其他期。原编辑页归档开关保留。

## 验证

- 新增持久化回归：只归档选中期、分配与进度读回、重复归档保持原时间、恢复推荐资格，以及归档／恢复保存失败后的状态回滚。
- 新增独立模拟器夹具及备份往返回归，覆盖跨年／月末的三期系列与推荐／手动交易。
- 新增四条原生 UI 回归：矛盾配置提醒与允许保存后重启读回；最大辅助字号的交易分组、手动金额、收键盘、就地错误及保存读回；单期归档与恢复；删除确认取消及实际删除后相邻期保留。
- 本地 Swift 6.0 Docker 语法检查已通过；宿主没有 Apple SDK，语法检查不能替代 SwiftData、SwiftUI 原生编译或设备验收。原生完整 CI 结果取得后另行记录。

本轮不包含报名日期补录和活动状态筛选，也不扩展银行资格判断、奖励计算或系列批量归档。
