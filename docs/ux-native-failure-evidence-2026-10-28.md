# 原生 UI 失败取证补修

[PR #67](https://github.com/maxduke/card-pilot/pull/67) 的 HEAD `2947e6a` 在
[40639124042](https://github.com/maxduke/card-pilot/actions/runs/40639124042) 完整通过 326 项，
八张相关原图已逐张实际验收。合并提交 `755b57e` 的源码树与该 HEAD 相同，但
[main 40653472777](https://github.com/maxduke/card-pilot/actions/runs/40653472777) 为 325 项通过、一项失败、零跳过。
促销概览用例在 `UI Reached` 返回列表后查询导航栏超时；随后失败取图也等待应用 AX 响应，
用例超过原有 240 秒额度，测试进程重启一次。没有用例重执行或 workflow 重跑，失败记录保留。

系统 spindump 包含对应应用 PID 96808：主线程的 404 个样本位于原生导航栏返回动画、底栏布局和
SwiftUI 无障碍视图更新路径，采样期间主线程使用 3.849 秒 CPU。失败前原图显示正确的已达标详情，
最后返回点击坐标为 `(32.1667, 78.3333)`。这些证据定位了等待发生的路径，尚不能确定最终原因。

有界诊断比较了原位置与循环结束后执行文字裁切审计。临时源码 `ecafaf0` 的
[原位置对照](https://github.com/maxduke/card-pilot/actions/runs/40693059548) 完成 15 次普通字号返回和原最大字号流程；
同轮另一组在新增的全局标识查询处同时命中列表和详情，仍记为失败。把该新增检查限定到实际详情列表后，
临时源码 `3e2328c` 的[结束后审计对照](https://github.com/maxduke/card-pilot/actions/runs/40697581608)
也完成同样 15 次返回、一次审计和最大字号流程。各次用例均只执行一次，无用例重试、workflow 重跑、进程重启或超时；
不能据此认定审计顺序是原因或原生卡住已修复。三轮循环、600 秒额度、编译标志和诊断 workflow 均不进入本补修。

本次只修正已确认的取证缺口：后台监听按测试分别保留第一次空闲异常，最多八项，记录对应测试名、时间、
实际应用 PID、采样结果及屏幕；较早用例的事件不再用掉整套测试唯一的采样机会。
失败清理改用 `XCUIScreen` 获取实际屏幕；当 XCTest 已报告 UI 查询超时，保留原失败并记录原因，
不再向同一无响应 AX 接口请求层级。普通断言失败仍保留层级，`super.record`、失败计数和原应用终止均保留。

所有 95 项 UI 方法、原有业务／页面断言、审计位置、180／240 秒执行额度、150 分钟完整作业以及产品代码保持原样。
本地检查覆盖 Swift 条件语法、分段日志、跨测试继续采样、重复事件去重、采样失败后继续截图、八项上限，
并核对监听不会改变构建成功或失败的退出状态。这些检查不替代 Apple SDK 编译、实际无响应进程或完整原生回归。
接下来以当前 HEAD 的完整 326 项、相关原图、适用审查和合并后的完整主线作为交付门禁；本补修不宣称修复了原生返回卡住。
