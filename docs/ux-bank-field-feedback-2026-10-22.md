# UX 第二十四批：银行名称错误反馈 · 2026-10-22

基于已完成主线原生验证的 `e6799dcf956518eb7d98d2e6129094366dcde051`，继续 O13。银行编辑器原先把空名称错误放在表单末尾；输入改正后旧提示仍保留，长备注也可能使名称和错误不在同一可见区域。

## 实现

首次点击保存后，在名称字段下显示现有的 `InlineErrorView`，错误由当前去除首尾空白的名称计算。修正后即时消失；名称的有效性规则保持原样。保存时关闭名称或备注的文字键盘，在错误布局更新后滚动到名称，保留全部输入。

只增加编辑器本地的反馈与焦点状态和稳定滚动标识，不写入模型或编辑快照，也不增加通用校验层。保留整体存储失败提示；银行的名称归一化、备注、归档时间、保存、回滚和放弃修改路径保持原样。

## 验证范围

保留原有 75 项 UI 的方法体与断言，增加四项普通／最大字号的实际交互：

- 新建银行：仅触发错误后可以直接取消，不要求放弃未修改内容；输入空白名称与十四行备注，保存后检查应用自行显示完整名称和其下的完整错误，键盘已关闭。纠正名称后错误消失，备注仍在；保存并重启，检查唯一银行、去除首尾空白的名称及完整备注。
- 编辑已有银行：使用同样的名称错误和长备注，并切换归档。纠正后放弃修改，重启检查原银行名称、空备注与未归档状态；再次无修改关闭，不出现放弃确认。

最大字号流程在提交前把名称滚出完整可见范围。错误可见性沿用既有严格检查，不在提交后的断言中调用测试滚动；完整字段和错误必须位于导航及实际 Form 边界之间。四项新测试沿用默认 180 秒额度，不增加等待常量或放宽几何边界。

每项流程保留“名称首错定位”“名称纠正后错误消失”和“保存后读回／放弃后原值读回”三张截图，共十二张。交付要求 GitHub PR 与合并主线均完整通过 222 项单元／集成和 79 项 UI，零失败、零跳过、无重试、超时或测试进程重启；当前绿色 HEAD 的原图由主代理实际逐张验收。

继续使用现有 Xcode 16.4／iOS 18.5／iPhone 16 Pro、串行及完整套件。正式 workflow 不改动。Linux Swift 语法检查与保存路径比较仅作为本地补充；Apple SDK 编译与实际交互以 GitHub workflow 为准。真机 VoiceOver 和外接键盘仍属于 O21，不能由模拟器结果推定通过。
