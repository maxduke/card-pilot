# 交易金额和促销确认页优化

承接 0.1.10 发布后的四项检查结果，集中改善交易列表与确认促销页面；版本准备为 0.1.11、build 1。

## 已实现的行为

- 交易行继续使用独立、右对齐的金额区域。优先将数值与币种放在同一行；空间不足时先将币种移到下一行，数值整段显示。只有数值自身仍超出行宽时提供横向查看，并显示提示。保留全部 Decimal 数位、退款负号、冲正样式和完整的无障碍朗读文本，不缩小辅助字号或截断小数。
- 确认页展示优惠剩余笔数，使用已保存交易计算，不提前消耗本笔尚未保存的次数。未选中时分别说明报名、币种、门槛、已用完额度、不可叠加冲突和手动取消；提示保留手动核对或修正入口，不新增银行资格限制。
- 同名系列活动的标题显示期次；搜索、系列和非进行中活动补充日期范围及进行中／未开始／已结束／已归档状态。相同结束日使用标题和 ID 稳定排序。继续允许历史补录，清除搜索后保留已选历史期和人工金额。
- 有规则或排除项的活动提供“查看规则”折叠区，直接展示现有文字。展开状态按活动 ID 保存在当前表单中，不参与金额、选择、草稿或交易保存；保持至少 44pt 的操作区域。

现有自动预选判定、累计与逐笔计算、退款和冲正规则、数据 Schema 及备份格式沿用既有实现。活动状态使用应用现有的 `currentDay`，不会引入另一套时区或日期刷新。

## 验证范围

- 原有两项金额布局流程增加数值单行、完整内容及可见范围检查；SE 3 最大辅助字号复核 `1,234,567.89` 不在小数中间断行。
- 新增最大辅助字号超长精度金额的真实横向滑动，检查所有数位保留、滚动位置变化及交易详情仍可打开。
- 新增最大辅助字号的剩余次数、未预选提示与手动修正返回读回；另一完整流程检查规则／排除项查阅、人工金额、返回修改及保存后重启读回。
- 新增同名四期活动的搜索、状态与日期辨认、历史期人工计入金额、保存后重启并编辑读回。
- 新增不可叠加候选的原因说明、手动选择单项保存及重启读回。
- 两项夹具测试通过真实备份验证、跨月／跨年日期、唯一活动身份、剩余笔数与超长小数金额读回检查数据有效性。

本地宿主没有 iOS SDK，只执行 Swift 语法、补丁检查和工作流脚本验证。原生门禁按当前最终提交执行 248 项单元／集成、109 项 UI（四分区预期 276／27／27／27），以及 8 项 SE 3 深色／增强对比度检查。SE 分为金额和表单两组，各运行四项完整流程，保留每组原有 25 分钟时限；汇总 `test` 门禁同时要求原生四分区和两组 SE 全部成功。通过后还需查看真实截图，确认文字、金额与规则的实际排版。

## 首轮 SE 原生检查与补修

- 实际层级显示 `1,234,567.89` 的单行宽度为 316.5pt，行内可用宽度为 311pt。数值使用随字号变化的轻微字距收紧，保留字形高度和全部数位，避免常见金额仅差 5.5pt 就需要横向查看。币种与数值之间的间隔也随字号变化。

## 第二轮原生检查与补修

[第二轮检查](https://github.com/maxduke/card-pilot/actions/runs/42440714278) 使用合并引用 `a650a3b856ed762b3306b90147e97d0901990b7c`。原始 SE 报告保留于 `/tmp/cardpilot-pr80-se-repair-failed`；原合并用例超过 240 秒后触发测试进程重启，随后 SE 作业达到既有 25 分钟时限并取消。证据导出的 `xcresulttool` 因结果包元数据尚未完整写入退出 64，`summary.json` 为空，不能根据日志里已完成的用例推算完整通过数量。

长精度用例的通用定位器要求内部滚动视图具备无障碍点击位置，但交易行拥有完整的无障碍标签；因此定位器在实际已可见的位置继续上下滚动，在开始横向拖动前失败。当前仅在该用例中按原生滚动区域的完整物理边界对齐，仍要求前台、启用、完整可见和至少 44pt 的区域，然后在该区域内真实横向拖动，并严格检查内容至少移动 20pt、所有数位保持不变和详情仍能打开。未移除产品的完整行朗读或改变通用定位条件。

原合并用例完成规则折叠后，在长列表中继续定位其他活动，最终超过原有 240 秒额度；日志未显示折叠操作长时间等待。现分成两个独立任务：未预选原因与人工修正，以及规则查阅与人工金额的返回、保存、重启读回。后一任务先使用真实搜索缩小列表，保留两个叠加活动；查阅规则、返回修改、保存和重启在同一用例完成。两项均保留 240 秒额度，不增加滚动次数或跳过交互步骤。

同轮分区 1 的历史期用例在清空搜索前失败：字段位于 y142–164，虽在导航栏下方，却被 y128–176 的固定步骤栏遮挡；失败截图及层级确认了这一位置。该流程全部改用已有确认页定位器，同时传入步骤栏、滚动区域和固定底栏；保留搜索清除、历史期人工金额、保存后重启编辑的完整断言。证据保留于 `/tmp/cardpilot-pr80-shard1-repair`。

分区 3 的原有账期历史用例在 180 秒额度报超时，随后仍完成全部原有筛选、详情返回、清除和 23 个账期读回断言，于 208.85 秒进入清理。日志包含一次 60 秒原生动画完成通知等待；据该次完整流程实测，将单项额度校准为相邻账期流程已使用的 240 秒，保留全部业务断言与原生动画。证据保留于 `/tmp/cardpilot-pr80-shard3-repair`；这不是账期逻辑或偶发动画卡顿根因的修复。
