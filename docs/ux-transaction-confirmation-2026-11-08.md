# 交易金额和促销确认页优化

承接 0.1.10 发布后的四项检查结果，集中改善交易列表与确认促销页面；版本准备为 0.1.11、build 1。

## 已实现的行为

- 交易行继续使用独立、右对齐的金额区域。优先将数值与币种放在同一行；空间不足时先将币种移到下一行，数值整段显示。只有数值自身仍超出行宽时提供横向查看，并显示提示。保留全部 Decimal 数位、退款负号、冲正样式和完整的无障碍朗读文本，不缩小辅助字号或截断小数。
- 确认页展示优惠剩余笔数，使用已保存交易计算，不提前消耗本笔尚未保存的次数。未选中时分别说明报名、币种、门槛、已用完额度、不可叠加冲突和手动取消；提示保留手动核对或修正入口，不新增银行资格限制。
- 同名系列活动的标题显示期次；搜索、系列和非进行中活动补充日期范围及进行中／未开始／已结束／已归档状态。相同结束日使用标题和 ID 稳定排序。继续允许历史补录，清除搜索后保留已选历史期和人工金额。
- 有规则或排除项的活动提供“查看规则”折叠区，直接展示现有文字。展开状态按活动 ID 保存在当前表单中，不参与金额、选择、草稿或交易保存；保持至少 44pt 的操作区域。

现有自动预选判定、累计与逐笔计算、退款和冲正规则、数据 Schema 及备份格式沿用既有实现。活动状态使用应用现有的 `currentDay`，不会引入另一套时区或日期刷新。

## 验证范围

- 原有两项金额布局流程增加数值单行、完整内容及可见范围检查；SE 3 最大辅助字号复核 `1,234,567.89` 不在小数中间断行。
- 新增最大辅助字号超长精度金额的真实横向滑动，检查所有数位保留、滚动位置变化及交易详情仍可打开。
- 新增最大辅助字号的剩余次数、未预选提示、规则／排除项查阅、人工金额与手动修正的返回读回流程。
- 新增同名四期活动的搜索、状态与日期辨认、历史期人工计入金额、保存后重启并编辑读回。
- 新增不可叠加候选的原因说明、手动选择单项保存及重启读回。
- 两项夹具测试通过真实备份验证、跨月／跨年日期、唯一活动身份、剩余笔数与超长小数金额读回检查数据有效性。

本地宿主没有 iOS SDK，只执行 Swift 语法、补丁检查和工作流脚本验证。原生门禁按当前最终提交执行 248 项单元／集成、108 项 UI（四分区预期 275／27／27／27），并增加至 7 项 SE 3 深色／增强对比度检查。通过后还需查看真实截图，确认文字、金额与规则的实际排版。

## 首轮 SE 原生检查与补修

[PR #80 首轮原生检查](https://github.com/maxduke/card-pilot/actions/runs/42436311752) 的 SE 为 4／7，三项未通过，原始报告保留于 `/tmp/cardpilot-pr80-se-failed`。源码为 PR 合并引用 `58b2bf6f004007c865fd9dc8104852fb817fb53e`，对应功能提交 `781280f`。

- 实际层级显示 `1,234,567.89` 的单行宽度为 316.5pt，行内可用宽度为 311pt。数值使用随字号变化的轻微字距收紧，保留字形高度和全部数位，避免常见金额仅差 5.5pt 就需要横向查看。币种与数值之间的间隔也随字号变化。
- 交易行继续拥有完整的无障碍标签，内部原生横向滚动视图不会暴露所设的 SwiftUI 标识或内部文本标签。长精度用例改为在唯一交易行内定位实际原生滚动区域，检查完整金额朗读、内容宽度与高度、真实横向位移及详情点击；不再要求被整行标签接管的内部文本节点。
- 普通金额用例先将数字滚入实际可见范围，再读取数值；继续检查单行高度、横向边界、完整数位与详情入口。
- 最大字号确认页的最后金额输入框距离返回后的初始位置较远。按活动行再到输入框的顺序导航，并使用实际步骤栏与固定底栏边界校验。各类提示去除重复措辞，保留原因与手动修正含义。未增加通用滚动次数、放宽几何检查或改变用例时限。
