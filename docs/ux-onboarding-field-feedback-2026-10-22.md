# UX 第二十三批：添加信用卡向导的字段反馈 · 2026-10-22

基于已完成完整原生验证的 `9a807fd` 继续 O13。向导的无效额度、空产品名称、错误末四位和空自定义卡组织此前只设置步骤底部的错误字符串；长步骤不会定位首错，改正输入后旧提示仍保留。

## 实现

沿用现有 `InlineErrorView`：点“继续／完成”之后，在当前步骤的字段旁显示具体要求；按可视输入顺序定位首个错误。反馈直接读取当前输入，改正后即时消失，尚未提交时不报错。步骤往返保留原输入，进入另一阶段时重置该次提交的反馈。

向导使用小型本地字段枚举、现有 ScrollView 的 `ScrollViewReader` 和稳定字段锚点。定位前收起当前键盘，异步布局后再次确认步骤及错误仍匹配。文本焦点覆盖向导输入，“收起键盘”仍只出现在额度和末四位；原来的固定上一步／继续／完成区仍为唯一主操作区。

字段提示与提交防御共用原有规则：额度可空或为正数，币种沿用现有选择，末四位为四个 ASCII 数字且保留前导零，自定义卡组织按原逻辑匹配／创建。首错检查先于模型创建；账户关系、规则、首期已还事实、保存／回滚及首次建卡提醒路径继续使用原实现。其他编辑器的错误处理仍按 O13 推进。

## 验证与交付门槛

四项新原生流程使用已有 `core` 夹具，各保留完整纠错与重启读回：

- 普通／最大字号额度：真实提交 `0`，不进入下一步；检查字段和完整错误都由应用定位到可见区域。改为 `125.50` 后即时清除错误，往返步骤保留值；普通字号保存后重启确认唯一卡片、`0123` 和 `125.5 CNY`，最大字号放弃后重启确认未新增卡片且原卡仍在。
- 普通／最大字号身份：同时准备空产品名、`123` 和空自定义卡组织；从步骤底部提交后依次确认产品名、末四位、卡组织首错。修正每项后旧错误即时消失，键盘切换保持原入口；普通字号保存后重启核对唯一卡片、前导零及自定义卡组织，最大字号放弃后核对原数据。

错误检查不在提交后用测试手势补定位；使用现有严格导航栏、滚动区域与固定页脚边界，另验收真实原图的内部文字。保留原有 70 项 UI 覆盖、断言及执行额度，新增四项向导流程使用现有默认 180 秒额度。下述既有账期审计拆分后，完整正式 PR 与合并主线均须通过 222 项单元／集成和 75 项 UI，零失败、零跳过，无超时、重试或进程重启。Xcode 16.4／iOS 18.5、iPhone 16 Pro、串行、默认 180／最大 240 秒、作业 150 分钟保持不变；本地 Swift 语法解析不能替代 Apple 平台编译与原生交互。
