# 第二十七批：单卡交易历史复用分组

基于第二十六批已验证主线 `4de8323`。其原生采样证实，全量交易页在每个 Section 读取计算属性会重复筛选、分组和排序整个结果集。单卡入口 `CardTransactionHistoryView` 仍使用同样的写法：`transactionSections[index]` 再次筛选全部交易，再对该卡全部记录分组。

本批在 `body` 中保存本次更新的卡片交易数组，在非空分支计算一次分组，所有 Section 读取同一份结果。沿用原卡片 UUID 判断、分组函数、日期／UUID 排序、Section 索引及各行身份；空状态、详情、使用当前卡添加交易和编辑器的全量上下文保持原样。没有跨更新缓存、额外状态、后台模型访问或 Schema 变化。

新增一项真实 UI 回归，复用已有两万笔隔离夹具：20 张卡、每卡一千笔、五年日期范围。通过卡片搜索进入末张卡，核对一千笔统计、最新行及另一行的卡片身份；从单卡历史添加新交易，检查列表立即出现一次、卡片和金额正确，并返回卡片核对统计变为一千零一笔。三个界面检查点保留原图，复用现有输入、滚动、保存与等待能力。

原有 85 项 UI 用例保持原样，常规原生回归成为 223 项单元／集成加 86 项 UI，共 309 项。先执行新增用例的原生预检，再走正式 PR、完整 CI、适用审查与原图检查、合并主线验证。工作流与原有预算不变，新增用例使用默认时限。

该 Debug 流程验证大数据下页面可完成操作及数据更新，不替代 Release 耗时、峰值内存或真机流畅度测量，也不产生新的性能提升百分比。第二十六批 21 项实际基线仍属于记录中的诊断源码，不能冒记为本批二进制的测量。现阶段已完成源码修改，原生预检与正式交付仍待执行。
