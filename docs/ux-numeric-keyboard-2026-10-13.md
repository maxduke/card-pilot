# UX 第十五批：交易金额键盘退出 · 2026-10-13

基于第十四批已验证主线 `b6bdaf7`，处理 O13 中交易表单的数字键盘退出路径。[PR #37](https://github.com/maxduke/card-pilot/pull/37) 首轮完整原生 CI 已通过，但截图发现最大辅助字号的既有步骤标题裁切，暂不合并。补修仍待新的完整原生 CI、当前 HEAD 截图检查和合并后的 main 验证。

## 行为

交易金额和促销计入金额聚焦时，在系统键盘工具栏右侧提供“收起键盘”按钮，点击区域至少 44 点。点击结束输入，保留金额原文、地区小数格式和手动分配，不触发提交或关闭编辑页。普通商户等文字字段不显示这个仅管理数字字段的按钮。

使用编辑页内部的可选焦点枚举，区分交易金额和各活动 UUID 对应的计入金额。新建表单自动聚焦、固定提交、手动选择活动、卡片选择和原消费选择沿用原来的焦点操作；滚动收起键盘、固定提交区、取消保护和草稿保存继续使用现有路径。收起动作仅清除焦点，不改金额、字段绑定、草稿快照或业务保存。

辅助字号下，顶部步骤说明使用可完整换行的“第 1 步，共 2 步：交易信息”或“第 2 步，共 2 步：确认促销”，避免两个放大圆点、分隔线和标题争用宽度。普通字号保留现有双步骤布局，所有字号保留完整无障碍说明，不限制系统字号。

## 验证

新增两个独立的原生 UI 用例，使用现有 core 夹具，原有 42 项用例和通用助手保持不变：

- 普通字号输入 `125.50`，真实点击工具栏按钮，确认键盘消失、原文保留和表单继续打开；编辑商户时不显示失效的数字字段按钮。将计入金额改为 `100.25`，再次收起并核对原文；终止和重启后继续草稿，确认手动分配保留，再实际保存、重启读回 `125.5 CNY` 交易及 `100.25 CNY` 计入金额，交易只创建一次。
- 最大辅助字号从第一次启动生效，分别操作交易金额和计入金额工具栏，检查完整无障碍标题、可点击性、44 点点击区域及屏幕内边界。两步分别核对完整步骤说明和屏幕内边界；收起后核对原值和编辑页仍在，步骤说明位于导航栏与固定操作区之间，固定提交及返回修改操作可到达且没有重叠，并执行两次不带排除条件的文字裁切审计。

第一轮补修 HEAD `a90424122a34ce8ebafc33605d26a5b9bc5a4731` 的 [完整原生 CI](https://github.com/maxduke/card-pilot/actions/runs/38290122967) 执行 218 项单元／集成测试和 44 项 UI 测试：单元／集成全部通过，UI 有 1 项失败、零跳过，产物为 `11768270295`。最大字号用例在第一次输入前的定位失败，尚未执行后面的步骤断言与裁切审计。失败截图中的步骤文字已完整换行；原生层级显示导航栏底部为 201 点，固定步骤说明底部为约 323.3 点，而定位助手只使用导航栏底部，导致金额框被步骤说明遮挡时仍反复上下滚动。

后续补修给步骤说明提供明确的布局容器；定位助手增加可选固定标题参数，仅本批最大字号用例的三个字段定位调用提供该参数，将步骤说明底部纳入可见区域。其他调用保留原来的计算方式、八次定位上限、滚动手势、底部遮挡检查、点击要求及几何精度。两次输入仍分别真实点击字段一次，使用原来的输入和删除原文方式；两次键盘收起及全部断言、截图和不带排除条件的裁切审计保留。

两轮补修均已通过两份 Swift 文件的 Swift 6 语法解析及差异检查。后续范围检查确认其余 43 项用例、其他助手及未传入固定标题的定位行为保持原文，旧断言、截图、两次直接收起及两次完整审计均保留；44 项用例名称、夹具与 workflow 保持不变。本地解析不能替代 Apple 平台编译、原生文字裁切审计或新 HEAD 截图验收。

本批仅处理交易表单的两个数字输入类型。其他编辑器的数字键盘、首个错误字段定位，以及真机、外接键盘和 VoiceOver 操作仍按 O13／O21 逐项验收。
