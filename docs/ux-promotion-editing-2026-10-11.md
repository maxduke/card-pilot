# UX 第五批：促销分组编辑 · 2026-10-11

处理 [产品评估](product-ux-review-2026-10-10.md) 的 O11，基于第四批已验证主线 `bdff161`。原来编辑已有促销仍从第一步开始，修改奖励说明也需要逐步到第三步才能保存。本批复用原有三个内容分组和完整保存流程，不增加模型字段、依赖或新的表单框架。

## 行为

- 促销详情的编辑按钮提供“编辑基本信息”“编辑适用范围”“编辑报名与规则”，直接打开所选内容；从促销列表的编辑入口进入时默认打开基本信息。
- 已有促销用原生菜单选择器切换编辑内容，每个分组都可以保存。切换时回到表单顶部，已输入内容保存在编辑器状态中；仅切换分组不计为内容修改。
- 新建促销仍按基本信息、适用范围、报名与规则三步引导；第一步验证后才能继续，最后一步保存。
- 系列活动的编辑范围始终显示在分组内容之前，默认“仅本期”。规则修改按所选范围生效，报名状态、报名日期和归档仍只修改本期；系列日期保护、已有分配的币种锁定、持久化回滚沿用原路径。
- 保存始终检查完整表单，基本信息或金额错误返回基本信息，报名截止日错误返回报名与规则；错误行放在当前分组字段之前。修改后取消仍需确认放弃；没有修改时取消直接关闭。
- 编辑器导航标题使用行内模式，为最大辅助字号下的内容保留空间。菜单使用系统控件，保留辅助功能标签与当前选择。

## 验证

新增三条 UI 回归覆盖：直接进入规则、跨分组修改后从基本信息保存、重启读回、取消修改后原值保留；新建三步引导与标题验证、跨分组保存时拒绝空标题并返回基本信息；最大辅助字号下的分组尺寸增长、点击区域、分组切换和直接保存。保留普通编辑、校验反馈、最大字号规则与适用范围的原生截图。

两个修改 Swift 文件已通过本地 Swift 6 语法解析，diff 检查通过。Linux 没有 iOS SDK，语法检查不验证 SwiftUI 类型或原生交互。交付须运行未裁剪的 GitHub iOS workflow，预期 199 项单元／集成测试和 20 项 UI 测试；PR 当前提交通过并检查截图后才合并，合并后再验证 main。本批原生结果尚待验证。

## 验收边界

模拟器测试不代表 VoiceOver 听觉、真实设备键盘或最小支持屏幕已经验收。真机需检查菜单阅读顺序、当前编辑内容的播报、金额与多行规则输入、键盘打开时的保存／取消，以及系列“仅本期／本期及以后”的辨识。本批不调整促销计算口径、持久化结构或通知排程，不包含 O12 的促销详情信息顺序重排。
