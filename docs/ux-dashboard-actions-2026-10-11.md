# UX 第八批：首页待办入口 · 2026-10-11

基于已验证主线 `b9e9c24`，接续促销规则解释，处理产品评估 O07：让首页的近期事项数量直接对应可处理的列表，沿用现有账户日程和详情入口。

## 行为

- 逾期、今天、未来 7 天变为原生按钮；点击后筛选并滚动到对应待办，再点击已选按钮或“显示全部待办”可恢复全部。说明数量包含还款与报名事项，选中状态同时用背景、字重和无障碍 trait 表达。
- 数量与列表共用自然日期／逾期状态分类：未来 7 天不含今天，包含第七天；报名截止事项沿用现有资格筛选，未来开始但即将截止报名的活动继续出现。
- 待办保持原有账期详情、促销详情和就地还款操作。还款后保留现有撤销提示；筛选中的最后一项处理完后显示明确空状态和恢复全部入口。
- 首页依旧按账户产生账务事项，共享账户不会因卡片数量重复显示还款。后续账户日程沿用最近账单和最近待还节点；筛选只作用于待办，不把其他时间段的待办搬到日程。
- 每个指标和恢复入口至少 44 点，文字适配辅助字号；滚动遵循减少动态效果设置。当前筛选保持在账期／促销详情返回后，跨日时使用新的自然日期重新计算。

本批不新增页面、模型字段、存储格式、通知规则或第三方依赖。账务条目的生成方法仅从视图属性提取为同文件函数，计算、去重、排序和常用时区参数保持原有行为，用于直接验证实际首页数据路径。

## 验证

- 日期边界单元测试覆盖跨年、今天、第七天／第八天、过去未逾期记录及不匹配日期的逾期标记。
- Debug 模拟器独立场景包含 20 张卡、4 个账户、1 项逾期、2 项今天待办与 2 项未来七天待办。完整备份验证及恢复读回在年初、月初、普通日期与年末运行；检查真实首页生成结果、共享账户去重及未来开始活动的报名截止。
- UI 回归检查三个指标与对应事项、两类详情导航、还款后的空状态和撤销、恢复全部、辅助字号点击范围，保留概览／今日待办／最大字号原生截图，并执行最大字号点击区域审计。

本地 Swift 6 语法解析和 diff 检查是补充验证；Linux 没有 iOS SDK。交付仍以未裁剪的 GitHub iOS workflow 为准，预期 202 项单元／集成测试和 24 项 UI 测试；最终 HEAD 全部通过、原生截图确认后合并，并再次验证 main。

20 张卡的功能场景不代表长期数据性能已测量，也不代替真实 VoiceOver、最小屏幕和还款提醒验收；O19 与 O21 继续按独立记录推进。
