# 完整备份与安全恢复（2026-09-08）

决策见 [ADR 0011](adr/0011-replace-backups-through-a-new-local-store.md)。本批不改 SwiftData V3 模型、不重置现有存储、不增加云同步或 CSV 导出。

## 文件约定

- UTF-8 JSON，顶层 `format: "CardPilotBackup"`、`version: 1`、`exportedAt`、`records`。格式版本独立于 SwiftData Schema，未知版本整份拒绝。
- `records` 必须包含 `banks`、`networks`、`accounts`、`cards`、`billingRules`、`billingCycles`、`promotions`、`transactions`、`allocations` 九个数组；不按活跃状态筛选。
- 对象使用原 UUID；单向关系保存被引用 UUID，反向集合在重建时还原。退款的原消费关系在全部交易建好后连接，文件中记录顺序无关。促销系列保留 `seriesID`、从零开始的 `seriesIndex`。
- 金额为 Foundation Decimal 的规范十进制字符串，拒绝 JSON 浮点数、NaN、尾随垃圾和不能无损表示的字符串；不经过 Double 或换算币种。自然日和账期分别保留 `YYYYMMDD`、`YYYYMM` 整数。
- 导出时间、归档时间与还款完成时间采用 Foundation Codable Date 的默认表示：自 2001-01-01 00:00:00 UTC 起的秒数，保留原 Date 精度；它们不参与自然日转换。
- 可选字段为缺省或 null；必填数组和字段缺失、结构损坏、重复对象 ID（包括跨类型）、重复关系引用、缺失引用、复合键冲突和领域约束错误均拒绝。文件不带加密，界面提示可信存放。
- 处理上限为 50 MiB、100,000 个对象；还款间隔最多 36,600 天、系列下标小于 120,000，拒绝超过自然日期支持范围的账期运算，避免导入后极端整数驱动无界计算或溢出。这些是格式 1 的导入与导出边界，不裁剪数据。
- 不包含 AppStorage：通知开关、提前天数、时刻、常用时区、应用锁、最近使用记录与派生通知状态均留在本机。

## 恢复事务

1. 选择文件并有界读取，校验版本、格式、唯一性、关系及模型约束；在内存容器中构建完整关系图。预览包含新旧数据数量、退款、系列数量及替换影响，取消不写磁盘。
2. 用户明确点击确认替换后再次校验，拒绝当前主上下文有未保存修改的情况。不合并，不按 UUID 更新原库。
3. 当前存储可读时，导出并原子保存独立的恢复前 JSON，再读回核对。不能生成、保存或核对备份时停止。
4. 在 Application Support / CardPilotRecovery 下创建随机 UUID 命名的新存储，保存后用新 ModelContext 读回所有字段和关系，与校验过的快照核对。
5. 最后原子写入 `active-store.json` 选择新存储，此为提交点。此前任何失败均不改变活动存储；原数据库及其 sidecar 文件不删除、不搬动、不覆盖。失败暂存库也不自动清理。
6. 更换根页面身份和 ModelContainer，关闭旧导航与 sheet，重新执行页面查询和通知重建。通知调度器跨根视图共享同一个串行写入器，避免旧根视图的进行中请求覆盖新计划。通知失败仍沿用已有错误提示与刷新入口。
7. 每次成功前保存的旧数据副本均显示在“恢复前备份”列表，点击使用相同校验、预览、确认流程找回；再次找回也会备份当时的当前数据。旧存储和备份不自动清理，会占用额外空间。本机副本不能代替外部导出。

启动使用选择文件指定的存储；没有选择文件时才使用原有 `CardPilotPrereleaseV3` 配置。选择文件损坏或指向缺失存储时显示错误，不创建空库、不回退原库。恢复后的空备份是合法的整库替换，重启不会偷偷补入卡组织。

容器启动失败时可重试打开，或进入备份恢复；恢复入口仍使用设备应用锁和后台独立窗口遮罩。界面说明检查设备解锁状态、可用空间和应用版本，禁止卸载或删除原存储。原存储不可读时不能统计或生成逻辑备份，此影响在预览和确认中明确显示，确认后在独立新库启用有效备份，原文件保留。

## 验证

- 新增 BackupTests，覆盖全部模型字段和反向关系、精确金额、共享账户、历史/未来规则、关闭账户、归档、停用、系列、退款及分配；覆盖重复 ID、引用缺失、复合键冲突、未知状态/版本、损坏文件、金额格式与领域约束。
- 故障注入覆盖恢复前备份写入失败、新库保存失败、读回核对失败、活动存储切换失败；断言原数据一致、选择文件不变、重新启动仍打开原存储。覆盖启动失败恢复、损坏选择文件、找回旧数据、空备份和未保存编辑保护。
- Linux：全部 Swift 源码语法解析通过；备份 DTO 与映射使用隔离类型检查通过；53 项隔离 XCTest（包括金额格式和文件大小测试）通过。隔离环境移除 SwiftData 宏并使用通知替身，不代表原生持久化、UI 或设备认证验收。
- 原生 iOS 构建和 XCTest 由本批 PR 的 iOS CI 验证，结果记录在 PR。真机验收仍需执行下列流程。

## 真机验收

1. 有共享账户、历史规则、归档促销、停用卡、退款分配的数据导出到“文件”，修改数据后导入；对照预览，取消一次，再确认一次；检查首页、卡片、促销、交易与提醒计划。
2. 从“恢复前备份”找回替换前状态；终止并重启，检查仍为所选数据。导出后跨设备恢复，确认自然日期不变、设备设置不被覆盖。
3. 使用损坏、重复 ID 和不支持版本文件，确认没有进入可提交的预览；模拟磁盘空间不足，确认没有替换原数据。
4. 开启应用锁，在导出系统面板、文件选择、预览和确认期间切后台并解锁，检查 sheet 与应用切换器无泄露；认证失败仍无法操作。
5. 在测试设备制造无法打开的存储或损坏的选择文件，确认显示重试/恢复路径而非清库；从有效备份恢复后原文件仍存在。
6. 检查深色模式、最大辅助字号和 VoiceOver 下的数量预览、确认动作及恢复前备份列表。
