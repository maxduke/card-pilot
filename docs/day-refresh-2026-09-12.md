# 跨日与时区刷新

本批为日期相关展示提供统一的 `CurrentDay`（常用时区与自然日期），由根页面持有 `DayClock`，通过 SwiftUI environment 传递到导航和 sheet。不修改数据库 Schema 或已保存日期。

## 刷新行为

- 首次显示和场景回到 active 时立即读取当前时间，补齐后台跨日、跨月或多日未打开的变化。
- active 场景持有可取消的异步任务，睡眠到常用时区下一个自然日边界后更新。按 Gregorian Calendar 计算边界，支持夏令时 23／25 小时日及历史午夜跳时，不采用固定 24 小时轮询。
- 修改常用时区、收到系统重大时间变化或设备时区变化时，重新读取日期并重启等待任务。设备旅行时区变化不会改写用户设置的常用时区。旧任务取消后不能再发布旧时区日期。
- 首页待办与促销期限、卡片和账户摘要与详情、账期详情、促销列表代表期和详情状态、建卡账期预览及月份选择窗口读取统一日期。已经进入的促销详情仍保留用户选择的期，只更新状态文字。
- 日期变化加入通知重建条件；前台返回及系统时间调整即使没有改变自然日，也会重建提醒。通知仍使用现有串行调度器及数量上限。
- 更新环境值，不重设根页面、导航或 sheet 的身份；已有编辑字段与选中的账期保持原值。表单初始化日期和保存时的真实事件时间继续按原有逻辑处理。

## 自动验证

- `DayClockTests`：常用时区午夜、跨年、非整小时时区、夏令时、午夜跳时、多日恢复、时钟回拨、时区前后切换、同日不重复发布、午夜循环及旧任务取消。
- `DayRefreshIntegrationTests`：统一日期推进后，账户摘要与账期详情从待还变为逾期；首页报名期限与继续完成活动、卡片适用活动及系列代表期同步切换；账期身份和已保存事实不变。
- 本地 Swift 6.1 Linux 隔离运行 7 项时钟测试通过，全部 Swift 源码语法解析及 `git diff --check` 通过。SwiftUI、SwiftData 集成测试与已有 UI 回归由 PR 原生 iOS CI 验证，结果以 PR 为准。
- 首轮原生 CI 的 148 项单元／集成测试通过。草稿丢弃 UI 回归暴露了辅助函数只会向一个方向滚动的问题：编辑页已关闭，目标按钮位于屏幕上方，辅助函数继续向下翻页导致失败。已根据目标位置选择滚动方向，完整 UI 回归随修正重新验证。

## 手动验收（待执行）

1. 常用时区设置为上海或香港，停留首页跨过午夜：当天还款变为逾期，报名截止与促销起止边界同步变化。月末重复，检查新月份账期与促销系列代表期。
2. 分别停留卡片、账户、账期与促销详情跨日；已选历史账期／促销期保持不变，相对日期和状态更新。
3. 在交易第二步输入手动计入金额，后台跨日后返回：输入、选择、步骤保留，关闭表单后首页状态已刷新。账户日期编辑和促销编辑同样检查。
4. 修改常用时区使“今天”前进或后退一天，检查上述页面与通知计划；再只改变设备时区，确认常用时区保持不变。
5. 在测试设备调整系统时钟并返回应用；检查日期回拨、跨日和仅时刻变化后的提醒计划。开启应用锁重复后台返回流程。

系统时间事件、真实通知与真机呈现保留属于手动验收范围，不由纯时钟测试推定通过。
