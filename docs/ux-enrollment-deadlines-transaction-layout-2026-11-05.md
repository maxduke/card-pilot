# 报名截止提醒与交易金额布局

基于 `5e2c521` 核对本轮真机反馈，并继续检查交易、促销、首页和提醒设置之间的信息一致性。

## 发现与修改

| 优先级 | 已确认的问题 | 本轮修改 |
| --- | --- | --- |
| P1 | 只有账单日、还款日会安排本地通知；报名截止仅在首页提示 | 增加可开关的报名截止提醒，默认提前 1 天和当天，共用固定时刻与时区；可调整提前天数 |
| P1 | 交易行按每条商户、卡片、促销文字的宽度选择横排或上下排，造成金额位置不一致 | 所有交易金额固定在独立一行并右对齐，保留币种、精确金额、退款符号和冲正样式；完整交易列表与单卡历史复用同一行 |
| P2 | 促销列表缺少报名截止日期，截止后仍显示待报名 | 列表直接显示截止日期；列表和详情统一区分尚未报名、报名已截止、已报名；详情提供提醒设置入口 |
| P2 | 全部活动归档后，空页面仍称“还没有促销活动” | 明确活动仍在归档中，并提供直接查看入口 |
| P2 | 小屏最大字号下，交易行可见空白区域点击未打开详情；报名区块位于更新动作和分配列表之后，需要跨多屏查找 | 交易行使用完整矩形点击范围；报名与资格固定放在进度之后，报名状态变化时也不移动区块 |

## 提醒行为

- 仅对有明确报名截止日期、尚未报名、未归档且未结束的活动安排通知。活动尚未开始也可以提醒报名。
- 默认每天 09:00，沿用用户现有的全局时刻和固定时区；已过的提醒时刻不补发，不将结束日当作报名截止日。
- 记录已报名、修改截止日期或标题、归档、删除，以及调整全局开关、节点、时刻或时区后，重新生成计划；沿用现有串行调度，旧的在途请求不能恢复已取消的提醒。
- 账单、还款、报名共用最近 48 条通知的额度，按时间安排；同一时刻先还款、再报名、再出账。保留最早未安排日期提示和独立的测试通知。
- 点击报名通知打开对应活动，沿用冷启动去重、应用锁和编辑期间延后导航。活动已删除或被恢复的数据替换时，显示明确的不可用页面。
- 原账务通知的载荷格式和标识保留；模型、已发布数据格式和备份格式未改变。
