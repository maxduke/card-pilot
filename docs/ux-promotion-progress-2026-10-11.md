## 行为

- 详情在系列选择器之后先显示进度、结束日期和完整奖励说明，再显示原有两条更新入口。规则、排除项和备注继续在后文显示；奖励只展示一次，不截断用户输入。
- 累计门槛优先显示“还需／已达标”；纯金额上限显示“剩余可计入”；优惠次数显示“剩余可用 N 次／优惠次数已用完”。金额门槛达标保留绿色，上限用完使用中性状态，不作为必须完成的消费目标。列表的次数播报同步改为可用次数。
- 进度文字按可用宽度换行，不缩小辅助字号。详情的文字值在辅助字号下改为标题与值纵向排列，保留普通字号的原生 LabeledContent。
- 编辑器在辅助字号下用原生 inline Picker 展示报名状态和资格日期选项，较长的“未知（交易日或入账日）”完整换行；普通字号保留菜单。选择仍绑定原有状态并经过完整保存流程。

本批只修改展示与控件布局，不改变进度计算、资格规则、退款／冲正、系列编辑范围、Schema、备份格式或通知排程。长奖励和最大辅助字号页面仍需正常滚动；“首屏”断言针对 workflow 的普通字号设备。

## 验证

新增独立的模拟器 fixture 场景，不扩大旧 core 场景。覆盖累计门槛、门槛达标、纯金额上限、次数剩余和次数用完，并通过完整备份校验／恢复验证真实模型关系和不同进度结果。

新增两条 UI 回归：五种详情状态的普通字号首屏、结束日期与奖励、进度在记录入口之前、金额达标与次数上限文案区分、普通字号文字裁剪审计、最大字号进度增长；最大字号报名和完整资格选项的操作、保存后重启读回及详情文字。保留各类状态、最大字号进度、报名选项、资格选项及读回详情的原生截图。

四个修改 Swift 文件通过本地 Swift 6 语法解析，diff 检查通过。Linux 无 iOS SDK；语法解析不证明类型、原生交互或视觉正确。交付通过未裁剪的 GitHub iOS workflow，预期 200 项单元／集成测试和 22 项 UI 测试，当前 HEAD CI 通过且截图确认后合并，再验证 main。实际结果以关联 PR 与 Actions 为准。
