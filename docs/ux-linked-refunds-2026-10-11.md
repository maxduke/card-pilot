# UX 第九批：从原消费记录退款 · 2026-10-11

基于已验证主线 `ca319fd`，处理产品评估 O14：从消费详情直接记录退款，并能沿关联关系查看原消费与退款。

## 行为

- 消费详情的关联退款区提供“记录退款”。新表单预填原消费的卡片、交易币种及关联关系，金额留空；沿用已有退款金额、促销分配与超额确认流程。账户额度币种不同也不会覆盖原消费的交易币种。
- 所有新增交易入口继续共用草稿恢复。存在未完成草稿时，先选择继续原草稿或丢弃后新建退款；继续的草稿保留自己的类型、卡片、金额、币种及关联事实。未修改的预填表单可直接关闭，不留下空草稿。
- 原消费和退款行成为原生详情导航入口；共享同一个 NavigationStack，原生返回保留上下文。详情内容与呈现根分开，保存反馈仍只在现有详情根显示，编辑弹层继续登记到原有呈现追踪。
- 已冲正的消费仍可关联退款，录入处显示说明；退款作为独立事实保存，不自动冲正、不修改原消费金额。未关联退款沿用原有显示和编辑能力。
- 关联退款按交易日期由近到远排列，同日按稳定 UUID 排序。入口至少 44 点；辅助字号下关联行纵向排列金额与摘要。

本批不改变持久化 Schema、备份格式、退款／促销计算、草稿格式或通知规则，不增加第三方依赖。

## 验证

- 独立 Debug 模拟器场景包含账户额度 HKD、原消费 CNY、已关联部分退款、已冲正原消费和未关联退款。完整备份往返检查交易关系、币种、分配及净进度。
- UI 回归覆盖原消费预填、第二次部分退款、累计超额取消／确认、促销可退余额、保存后重启读回及关联详情往返；另检查已有无关草稿的继续／丢弃、空表单关闭与空金额换卡时币种保护。
- 最大辅助字号回归覆盖已冲正原消费的新退款、独立有效状态、关联导航、44 点入口及点击区域审计，并保留原生截图。

本地 Swift 6 语法解析及 diff 检查为补充；Linux 没有 iOS SDK。交付通过完整 GitHub iOS workflow，预计 203 项单元／集成测试和 28 项 UI 测试；最终 HEAD 全部通过、原生截图确认后合并，并再次验证 main。

模拟器检查不代替真实 VoiceOver、最小屏幕、系统键盘和银行账目核对；继续按 O21 验收。
