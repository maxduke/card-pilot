# 账户命名保留已发布存储与备份兼容

v0.1.7 已经发布，采用 V3（3.0.0）模型、v1 完整备份和 v1 交易草稿。
[ADR 0009](0009-reset-prerelease-store-for-schema-redesign.md) 只适用于可重建的开发数据，
不能用来清空已发布应用的账本。

v0.1.5、v0.1.6、v0.1.7 的模型与备份源码逐字相同，本批使用这组发布定义的样本。
更早的 V1／V2 存储身份及早期 V3 定义仍需单独核对，不将 v0.1.7 样本当作所有早期版本的升级验收。

账户名称采用一个可选的 `customName` 字段。留空继续使用已有的银行／卡片摘要；
设置后，换卡、修改卡片昵称或暂时没有关联卡片都不改变账户名称。名称不承担唯一键职责，
账户 UUID、共享关系、账务规则、历史账期及交易事实保持原语义。

模型版本推进到 V4（4.0.0），保留 `CardPilotPrereleaseV3` 配置名称和已选中的数据库 URL。
这次只增加可选字段，使用 SwiftData 的自动兼容迁移。
[Apple 的 ModelContainer 文档](https://developer.apple.com/documentation/swiftdata/modelcontainer)
说明了自动迁移，以及超出自动迁移能力时使用 `SchemaMigrationPlan` 的方式。
不将已改变的模型继续声明成历史 V3，也不为这次可选字段提前复制九类模型或引入自定义转换。
以后出现不兼容类型、约束或关系变更时，必须重新评估，并为确实需要的版本冻结定义和迁移阶段。

新导出采用 v2 备份并保留名称；当前版本同时读取实际 v1 备份。旧应用会拒绝 v2 头部，
从而避免接受文件后静默忽略名称。编码与解码均拒绝包含名称却标为 v1 的记录。
恢复仍在独立数据库保存、读回核对后切换选择；旧数据库与旧草稿保留，新的数据库身份不继承旧草稿。
交易草稿继续使用现有格式策略，实际 v1 草稿按原来的数字语义读取。

验证使用[实际发布源码生成的原生样本](../../CardPilotTests/Fixtures/README.md)，
不使用当前模型伪造旧库。原始文件保持不变，每项测试只打开独立副本。
原生门禁比较全部九类模型的字段、UUID 关系与落盘金额，检查原位打开、写入名称后重开、
旧备份恢复、草稿身份、恢复保存失败及无法读取旧库时的备份救援。
故意损坏副本头部的测试只证明该读取失败场景，不代表已模拟所有迁移中断或设备故障。

V4 与 v2 已在[原生 231 项单元／集成门禁](https://github.com/maxduke/card-pilot/actions/runs/40214434648)
通过，覆盖上述五项旧数据兼容与恢复用例；交互、原图及正式完整回归仍待执行。
样本来自 iOS 18.5 模拟器上的 v0.1.7 源码，不代表真实旧设备、iOS 17 升级或系统通知送达验收。
