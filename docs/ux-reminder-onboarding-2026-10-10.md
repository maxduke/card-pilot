# UX 第二批：首次建卡后的提醒引导 · 2026-10-10

对应 [产品评估](product-ux-review-2026-10-10.md) 的 O03，基于第一批已合并的主线 `662fd4d`。用户已授权后续每批通过原生 CI 后合并，并验证主线。

## 行为

- 第一张卡完整保存成功后显示保存确认、账户日程和“设置提醒／稍后设置”。账务日期使用现有账户摘要计算，包括已还账期与日期覆盖；它不等同于已安排通知的时间。
- 保存失败仍停留在编辑器；保存成功后的页面不再属于未保存编辑，关闭或稍后设置不出现丢弃警告，不回滚卡片。只有没有已有卡片时显示引导，后续加卡直接完成；不增加持久化引导标记。
- 建卡引导和设置页共用“通知与提醒”页面。设置首页保留备份与应用锁入口，提醒权限、两类提醒、提前节点、固定时区、测试提醒及计划集中到共用页面。
- 权限读取期间显示读取状态；仅在用户点击允许通知时请求系统权限，请求期间禁止重复提交。拒绝后提供系统设置入口；从后台返回刷新权限。授权成功继续通知现有 RootView 重建全局排程，不另建调度器或排程来源。
- 两类提醒均关闭时明确说明；通知权限、已安排条数、下一次提醒与最早未安排日期分别展示。下一次时间为空时显示“尚未安排”，保留最近 48 条计划与重新打开补充的覆盖边界。
- 使用系统 Form、NavigationStack、LabeledContent；完成／稍后操作固定在底部，最小高度 44 pt 放在按钮内容内，扩展区域参与点击。提醒页面的时区弹层挂在稳定容器，沿用已有呈现登记与通知等待规则。

保持持久化 Schema、备份及草稿格式，沿用现有通知排程、账务计算与全局设置键，不改变应用锁或真实权限的测试策略。

## 自动验证

- 扩展首次建卡 UI 回归：保存后显示引导，检查完成／稍后的实际尺寸并点击文字外侧关闭，不出现未保存警告，重启可打开已保存卡片。
- 新增 UI 回归：从引导进入共用设置，两个提醒开关独立，重启后从首页设置进入同一页面并读回开关；卡片没有重复保存。
- 新增 UI 回归：已有卡片时添加新卡不重复出现首次引导。
- 改动 Swift 源码通过本地语法检查；原生 Xcode 构建、全部单元／集成测试与 UI 测试仍由 PR 当前提交的 `iOS` workflow 验证，完成后合并并验证主线。

原生验证首先发现 `Section` 标题与 footer 的初始化写法不兼容，已改用明确的 header。之后 [原生 CI](https://github.com/maxduke/card-pilot/actions/runs/38060652133) 通过 199 项单元／集成测试与 12/13 条 UI 测试；失败用例的截图与层级显示，点击整个 Toggle 行没有切换原生开关，两类提醒仍开启。回归改为点击实际开关并立即核对状态；同时截图证实底部完成操作的实际区域约 34×20 pt，已扩展按钮内容并加几何和外侧点击检查。后续原生验证仍是合并门槛。

## 真机验收

1. 未请求权限时首次建卡：确认卡片已经保存、日程正确；点击允许通知后检查系统提示，并核对设置中的实际计划。
2. 拒绝权限，再进入引导／设置：到系统设置开启，返回应用确认权限与计划刷新；关闭提示和拒绝授权均不影响卡片。
3. 分别关闭两类提醒，检查独立开关、条数、下一次时间、权限与首页提示；两类均关闭时显示明确说明。
4. 修改固定时区、提前节点与提醒时刻，发送测试提醒；多账户超过 48 条时检查最早未安排日期，不推导出永久覆盖。
5. 最大辅助字号、VoiceOver、浅／深色下检查保存确认、账户日程、完成动作及提醒页面的可读性与导航焦点。实际送达还需切到后台／锁屏验证。

模拟器和 CI 通过不代表真实权限、通知送达、VoiceOver 或真机视觉验收完成。
