# 账户名称与已发布数据兼容

本批处理 O09，并建立 O22 的实际发布数据基线；实现与原生预检已通过，正式交付仍待最终 HEAD 完整回归及合并主线验证。

## 行为与范围

账户可填写名称，创建与编辑都支持；空白输入保存为未命名，继续使用原有默认摘要。
名称不随卡片昵称、换发末四位或关联卡片数量变化。列表、搜索、详情、账期及通知复用已有身份入口，
共享账户的名称搜索仍展示它的全部可见卡片。编辑快照、放弃修改和失败回滚都包含名称。

辅助字号下，账户行与卡片行沿用已有的纵向／横向自适应方式，为名称、末四位和还款信息留出完整宽度。
普通字号维持原有紧凑布局。未命名账户的详情标题保留银行名称，辅助标签仍包含完整账户身份；
自定义名称允许完整换行。

数据模型只增加可选 `customName`，版本推进到 V4，保留配置名称 `CardPilotPrereleaseV3` 与已选库 URL。
通过 SwiftData 自动迁移读取旧库。新导出使用 v2，读取实际 v1／v2 备份；包含名称却标为 v1 的文件会被拒绝。
导入预览保留原文件格式版本，恢复后重新导出使用当前格式。版本策略见 [ADR 0012](adr/0012-preserve-released-stores-for-account-names.md)。

## 实际旧数据样本

使用已发布 v0.1.7 的不可变源码 `437d303`，额外加入诊断 XCTest 与 workflow，生产模型、服务和工程保持原样。

实际 v1 备份、未完成 v1 草稿，以及哈希、工具链和源码清单。输入与来源说明见 [测试样本](../CardPilotTests/Fixtures/README.md)。

样本包含全部九类模型、25 条记录，覆盖共享／关闭账户、多版规则、已还账期、按月系列、归档、退款、撤销及精确金额字符串。
比较以旧版实际落盘值为准，不将 SwiftData 已归一化的大 Decimal 字面量当作原值。
测试只打开独立副本，原始文件保持不变。

五项兼容用例检查原位打开、全部字段和 UUID 关系、写入名称后重开、旧备份恢复与库选择、草稿身份、
旧数字语义、保存失败后继续使用原账本，以及无法读取旧库时保留原文件并从备份救援。
故意损坏副本头部的用例只覆盖该读取失败场景。
