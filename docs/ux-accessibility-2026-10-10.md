# UX 第三批：点击范围与辅助字号 · 2026-10-10

对应 [产品评估](product-ux-review-2026-10-10.md) 的 O04 中筛选、交易与账期日程的可操作性检查，基于第二批已验证的主线 `4e02dc0`。继续使用系统 SwiftUI 控件和已有导航，不增加数据字段、业务规则或依赖。

## 行为

- 交易筛选标签整块可点，文字和叉号属于同一个移除按钮；叉号不再是独立的微小操作。标签和清除全部的按钮内容至少 44×44 pt，保留现有筛选与清除逻辑。
- 首页“查看账期”使用整行点击区域，按钮内容至少 44 pt 高；辅助说明包含账户与账期，区分重复的入口。
- 商户、卡片身份和活动说明允许换行，避免窄屏或较长金额挤压身份文字。交易在内容能完整横向容纳时并排，否则金额独立成行；辅助字号下直接分行，状态标签纵向排列，保留精确金额口径。
- 首页通知入口整行至少 44 pt 高，活动适用卡与账户辅助说明允许换行。交易搜索提示缩短为“搜索交易”，匹配范围不变。
- 银行字母标识与银行 logo 使用同样的固定图标尺寸和图片辅助语义，避免最大字号把字母放大到图标框之外；银行名称与其他正文继续随字号缩放。
- 辅助字号下，账期状态与两类日期纵向排列；首页账务身份和日期分行。日期计算、共享账户与还款状态不变。
- 首页账务／活动图标与卡片快捷操作图标的占位宽度按相应文本样式缩放，避免大图标压到相邻正文。辅助字号下首页活动进度与结束日期分行，文字保留所需的完整高度。
- 提醒子页面使用原生返回导航与父层完成操作，移除额外的同名“完成”按钮，避免首次引导中上下两个完成入口执行不同关闭动作。

## 自动验证

- 保留第二批已补齐的首卡按钮尺寸与外侧点击回归。
- 新增交易筛选回归：保存包含小数的交易，检查原生列表；选择消费筛选，检查标签和清除全部的尺寸，点击标签文字区域后移除筛选且保留交易。
- 新增账期日程回归：检查卡片日程与首页，检查账期入口尺寸和账户说明，打开账期详情。
- 原生 UI 用例调用 [Apple XCTest 无障碍审计](https://developer.apple.com/documentation/xcuiautomation/xcuiapplication/performaccessibilityaudit(for:_:))，按页面检查文字裁切和点击区域。账期与交易另以最大辅助字号重启同一测试数据，先断言标题／金额实际高度大于常规字号的 1.3 倍，再验证筛选移除与账期导航，保留常规和最大字号截图到 workflow 的 xcresult 产物。
- 本地 Swift 语法和 diff 检查为补充；原生编译、全部单元／集成与 UI 测试由 PR 当前提交和合并后的 main workflow 验证。
