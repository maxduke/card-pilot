# UX 第十一批：完整账期回查 · 2026-10-11

基于第十批已验证主线 `c940b26`，处理产品评估 O16 的账期回查：保留账户详情的近期摘要，提供完整列表作为出口。未来规则管理单独推进，不在这批加入删除操作。

## 行为

- 账户详情的近期账期区提供“查看全部账期”，进入同一个导航栈，按年、月和已还／未还状态查找。列表按账期由近到远排列，显示匹配笔数，支持一键清除筛选。
- 复用现有账期生成口径：追踪开始至当前日期后两个月，加上已保存的历史与未来记录；保留追踪开始前的显式记录和已关闭账户的有效历史。按账期年月筛选，日期覆盖不会改变所属账期。
- 列表复用原有账期行和详情，继续支持还款标记、撤销及调整本期日期。详情返回保留筛选；处理最后一个匹配的未还账期后显示空状态，状态变化可继续通过筛选找到。
- 每个入口至少 44 点，沿用辅助字号账期行布局和明确的文字状态。年份来自可显示账期，并保留当前选择；跨日更新数据时不重置查找条件。

不修改规则、账务计算、稀疏账期存储、提醒身份、Schema 或备份格式，不引入第三方依赖。

## 验证

- 单元测试覆盖日期覆盖与账期年月的区别、按状态筛选、月份排序、关闭账户界限及追踪前已保存历史。
- 独立模拟器场景包含 23 个可显示账期、8 个已还与 15 个未还账期；在年初、普通日期和年末进行完整备份往返，核对共享账户关系和未来日期覆盖。
- UI 回归从摘要入口查找第七个已处理账期及第五个未还账期，验证详情返回和还款后的空状态，再从同账户另一张卡重启读回；最大辅助字号检查筛选、清除、无匹配状态和未来日期覆盖，采集原生截图及点击区域审计。

本地 Swift 6 语法解析和 diff 检查通过；实际筛选函数另在 Swift 6 下编译执行，验证排序、年／月条件及已还／未还分类。这些均为补充验证；完整 GitHub iOS workflow 的最终 PR 与合并后 main 已通过 209 项单元／集成测试和 32 项 UI 测试，实际运行与截图证据见下文。

此列表不是无限未来推演；长期性能、最小屏幕和真实 VoiceOver 继续独立验收。
