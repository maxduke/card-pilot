# 首批 UI / UX 实现 · 2026-09-05

基于 [审查报告](app-review-2026-09-05.md) 完成 R01–R06 的主要代码修复，并合入部分 R07–R13 的核心流程优化。此记录说明已实现范围与验证边界，不代表全部 17 项审查建议已经完成。

## 已实现

| 范围 | 当前行为 |
| --- | --- |
| 编辑与应用锁 | 根页面及 sheet 保持挂载；独立锁屏窗口覆盖内容、关闭键盘并屏蔽底层交互和无障碍访问。普通解锁不再清空编辑器或导航状态。 |
| 取消保护 | 添加卡、银行、账户、卡片、活动、交易和活动分配编辑器有修改时禁止下滑关闭，点击取消需确认放弃。成功保存正常退出。 |
| 提醒可靠性 | 重建串行处理，等待旧的系统添加请求结束后应用最新配置；已还款不会被旧重建重新加入还款提醒。添加失败时保留仍有效的原请求。 |
| 提醒窗口 | 最早 48 条按时间连续排序，同一时刻优先还款；提示使用最早未安排日期，避免用最晚已安排日期误报完整覆盖。 |
| 账户辨识 | 首页待办、还款撤销反馈、账户摘要及通知使用统一的银行、卡片名称和末四位摘要；VoiceOver 补充账单、还款与逾期信息。 |
| 适用卡语义 | 空集合显示“尚未选择适用卡”，解释不会自动推荐但可手动计入交易。 |
| 还款撤销 | 账户编辑中的“撤销已还款”只修改草稿；点击保存统一提交，取消不会改变原还款记录，可在表单内保留已还款状态。 |
| 导航 | 使用四个内容 Tab，并在原生底栏正中保留“记一笔”动作项；不再叠加整条快捷工具栏。从原页面直接打开录入，关闭后保留页面上下文。 |
| 添加卡片 | 没有同银行账户时跳过账户选择，共用已有账户时跳过账务录入；账务日期直接选择，显示本期计算预览并支持标记本期已还款。 |
| 日常记账 | 新交易聚焦金额；没有相关活动时直接保存，有候选、已选活动或待补入账日期的活动时进入确认页。保留手动搜索活动入口。 |
| 活动确认 | 显示交易摘要及底部冲突提示；未报名活动不自动勾选，多个自动候选含不可叠加活动时由用户选择，已有手动选择仍保留。 |
| 活动行动入口 | 列表突出奖励摘要；详情把“记录新消费”和“选择已有交易”统一放在“更新进度”区域，使用居中、等宽且至少 44 pt 高的主次按钮，移除空状态与工具栏中的重复入口。“标记已报名”归入报名信息。记录消费预选该活动及适用活跃卡，仍需确认计入金额。 |
| 设置与空状态 | 账单、还款提醒分别启停且保留节点；显示下一次提醒、最早未安排时间、安排条数及刷新入口。返回前台刷新权限。交易与活动空状态有直接行动按钮。 |
| 可读性 | 日期同时显示相对与绝对时间；还款动作至少 44 pt 高；金额改为语义大字号并在辅助字号下纵向排列；步骤数字使用独立前景/背景色并随字体缩放。 |

没有修改持久化 Schema；继续使用既有 SwiftData 模型、手动促销分配和本地通知。

新增回归覆盖：多账户按时间截断、同一时刻还款优先、已还款取消、保留非本应用请求、重建交错、添加失败保留有效请求、跨年相对日期、账户可辨认标签与无障碍日期、未报名活动不自动选择。
