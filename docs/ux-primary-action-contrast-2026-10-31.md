# 主按钮文字对比度

O04／O18／O21 的剩余验收核对发现，既有外观验证没有明确启用“增强对比度”。
基于已交付主线 `c1bbd08`，使用 Xcode 16.4／iOS 18.5／SE 3 复用三个原完整流程，
在浅／深色下明确设置增强对比度并前后读回。

## 原始证据

[运行 41176669371](https://github.com/maxduke/card-pilot/actions/runs/41176669371) 的深色通过三项，
浅色通过交易与促销，账期用例在卡片详情的审计中记录两处 `Text clipped`，没有关联元素。
每个用例在每种外观各执行一次，零跳过；49 张当前原始 PNG 已逐张实际查看。

另外确认一个独立的实际配色问题：深色增强对比度的交易主按钮使用白字配浅粉色底。
三张交易原图的平坦底色均为 sRGB `(255, 179, 165)`，实心字形为 `(255, 255, 255)`，
非边缘白色像素分别为 9862、8952、8952 个。按相对亮度公式得到约 `1.7152:1`；
这低于 [W3C 对普通文字 4.5:1、大字 3:1 的可读性参考](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
首个按钮随后确实打开第二步，采样对应可操作控件；该结论来自原生原图，不是只比较资源文件色值。

## 改动

11 个原生填充主按钮采用 `Color(uiColor: .systemBackground)` 作为文字色，
由系统外观提供浅色下的亮色文字和深色下的暗色文字。
覆盖交易提交、还款、建卡引导、空状态、草稿继续和锁定窗口的同类动作。
沿用原生 `.borderedProminent`、现有强调色和禁用处理，布局、字号、标签与业务动作沿用原路径。
各处复用同一个系统语义颜色。

原有 iOS workflow 的大屏完整作业保留；SE 3 深色作业明确启用增强对比度，
前后读回并上传实际设置。继续执行原有两项完整流程，不增加作业或用例执行次数。

## 账期审计的证据边界

两处未关联元素的报告仍保留为失败，尚未证明是布局缺陷或系统误报。
原图和层级中的目标账期完整显示，邻近文字处于滚动边缘；原报告不足以把问题指向某个文字。
单独的视口诊断只收集未过滤的报告、原图与层级，不作为原验收通过的证据。
正式 UI 测试和已有审计条件沿用原版本，视口诊断保存在独立诊断分支。
[视口诊断 41179191769](https://github.com/maxduke/card-pilot/actions/runs/41179191769) 的三张当前原图已实际查看：
首次完整账期和向上滚动分别记录零项，重新显示账期后记录两项，仍无关联元素。
同一账期在两次检查的高度均为 385.5 点，位置从 y＝218 变为 y＝222.5；两张原图中的账期均完整可读。
这些观察尚不足以确认报告原因；原两处失败继续保留，后续由辅助工具或真实使用复核。
